# 实验协议：契约感知的布尔电路重写

状态：研究计划与执行准则；当前仅有确定性 pilot。本文不报告尚未执行的模型实验、工具综合或物理结果。日期：2026-10-14。

## 1. 研究边界与当前证据

研究对象是两态、无状态、无环的组合布尔电路。拟研究的问题是：在明确且可证明适用的布尔契约下，候选生成器是否能在公平预算内发现有效的电路重写，以及 LLM 是否提供强传统搜索之外的收益。单纯将 LLM、等价检查和综合器串联不自动构成方法新意。

当前代码中的候选来自手工构造的 deterministic pilot，而非真实 LLM。checker 使用有界穷举，相关输入域分别最多 16 个布尔输入，并受 AST、深度及求值预算限制；局部输入少不代表外部环境输入也少。结构门数与逻辑深度是抽象代理量，不能换写为面积、功耗、延迟或硅测结果。pilot 用于发现实现错误与解释证明义务，不能作为独立基准、模型能力或泛化证据。具体运行结果以仓库实际生成的日志为准。

正式实验前必须解决：真实 LLM 接入与完整轨迹、可辩护的契约提取或反馈机制、强基线、现实规模设计的选择与整体验证、技术映射及 PPA 评价。当前穷举器本身不支持工业规模结论。

## 2. 正确性义务与可替换条件

令 x 为外部输入，u=B(x) 为待替换子电路的边界输入，F(u) 为原局部多输出函数，F′(u) 为候选，C(u) 为局部契约，A(x) 为外部合法输入条件。必须区分以下义务：

1. **外部合法性。** 系统规格或可信上游约束必须说明实际允许的输入满足 A，且 A 可满足。若没有独立依据，令 A=true。模型不得增加、删减、弱化或强化 A，也不得通过选择 A 排除失败输入。A 的来源、版本、审批依据与哈希随实例固定。穷举证明只能判断形式公式，不能证明真实环境确实遵守人为填写的 A。
2. **环境蕴含。** 证明对全部外部输入成立 A(x) ⇒ C(B(x))，不能只验证一组采样输入。B 必须取自未被重写破坏的原始上游逻辑，不能循环依赖候选输出。
3. **局部等价。** 证明对全部局部输入成立 C(u) ⇒ [F(u)=F′(u)]，其中等号覆盖全部对外可见输出。C 必须可满足；不可满足契约不能让任何候选获准。
4. **上下文替换。** 原电路可写作 G(x)=H(x,F(B(x)))，新电路为 G′(x)=H(x,F′(B(x)))；接口、位宽、端口映射、上游 B 与下游上下文 H 保持所证明的含义，所有跨边界连线均被纳入，组合依赖无环。由前述义务才能得到 A(x) ⇒ [G(x)=G′(x)]。正式集成后另做整体等价检查，以发现边界提取、翻译或连线错误。

局部 VERIFIED 只表示受当前语义和资源边界约束的局部命题已通过，不能单独解释为整个设计可安全替换。条件证明也不意味着无条件等价。导出的 Verilog 不会自动实施契约；调用方必须落实外部约束。四态 X/Z、锁存、时钟、复位、状态可达性、模拟效应和物理时序均超出本项目当前证明范围。

候选与可选的 C 可以由模型提出，但 A、参考 F、边界 B 和验证策略来自可信驱动程序，不能接受模型对其覆盖。解析失败、非法算子、接口变化、资源超限、超时或 UNKNOWN 均不得进入接受集合。SAT/UNSAT 的含义由具体查询定义记录：等价 miter 可满足意味着找到反例，不能机械将任何 SAT 当通过。

## 3. 三项可证伪研究问题

| 问题 | 主要检验 | 推翻或限制主张的证据 |
| --- | --- | --- |
| RQ1：明确的、已证明适用的契约是否提高有收益候选的产生效率？ | 同模型、同任务、同预算下，比较契约提示与无契约提示的有效改进率、首次改善总成本。两组均使用相同正确性门禁。 | 仅提高解析或等价通过率；计入契约提取和验证成本后，有收益候选率或最终收益没有优势。 |
| RQ2：LLM 是否提供传统重写或搜索之外的优化价值？ | 在相同端到端预算和固定时序约束下，与强综合/搜索基线比较映射面积；报告可行率和全部实例。 | 优势只存在于默认弱脚本、更多候选或更多综合调用；公平预算下强基线追平或超过。 |
| RQ3：真实反例反馈能否改善未见设计家族的搜索效率？ | 比较真实反例反馈、无反馈和预算匹配的非反例诊断反馈，考察冻结测试家族的有效改善概率及成本。 | 收益依赖开发家族，或反馈带来的额外 token、证明与等待成本抵消收益。 |

RQ3 若仅实现常见反馈循环，应作为消融问题，不单独宣称方法创新。实验可以产生零收益或负收益结论；不得据结果倒改主要问题或成功判据。

## 4. 基准、划分与许可

使用两类来源：有可核实出处和许可的现实组合逻辑/真实设计中提取的组合锥，以及依据公开规则生成的受控设计。现实规模必须以外部接口、节点数量、逻辑深度、扇出和完整设计大小描述；不能把多个微小公式拼成所谓工业评测。若仅获得学术开源设计，应准确使用该名称，不称工业设计。

抽取子电路的位置和大小策略须在测试前冻结，记录所有入选与排除原因。因 checker 限制而排除的实例计入覆盖率；不得只保留已知可简化的位置。先明确证明后端对更大实例的能力，不能通过选择小窗口掩盖整体规模缺口。

按设计家族分割开发、调参与最终测试集。同一生成模板、同一源设计的切片、不同位宽/参数变体及高度相似衍生设计归入同一 family，不能跨集合泄漏。开发集用于提示和预算调参；测试集冻结后禁止根据结果修改提示、规则或选择最有利种子。明确公开基准可能进入模型预训练，不能宣称彻底排除污染。

为每个源记录 URL、版本/提交、许可证、版权与再分发限制；PDK、标准单元库及工具许可独立核实。禁止上传受限网表、库文件、密钥或个人信息。无法再分发的材料以获授权的下载说明和内容哈希替代，披露其对第三方复现的限制。

## 5. 强基线与公平比较

所有优化方法使用相同问题定义、A、接口、正确性判据、映射库、时序约束和最终评估流程。

| 组别 | 要求 |
| --- | --- |
| Yosys/ABC | 记录精确版本、命令、脚本和映射选项；在开发集对适用的重写/重综合流程作合理调参，包括重复重写和预算允许的搜索。默认单次脚本不足以单独代表强基线。 |
| 非 LLM 搜索 | 使用同一边界、表达式语法和成本评估，至少纳入可实现的枚举/语法或随机搜索；按任务规模考虑精确综合、成熟局部重综合或 SAT 驱动搜索。 |
| LLM 直接候选 | 固定模型与提示，生成候选后使用相同验证和综合选择，作为基础 LLM 对照。 |
| LLM + 契约 | 与基础组固定相同模型、候选上限、采样设置和反馈策略，仅改变所研究的契约机制；计入提取、表示和证明成本。 |
| LLM + 契约 + 反例 | 在上述组上加入真实反例；与预算匹配的无反例/诊断反馈对照比较。 |

至少报告两种互补的预算视角：候选数/验证与综合调用上限一致；端到端实际时间或可核算计算成本上限一致。不同工具的内部一步不天然等价，所以不能只报迭代轮数。所有组记录 CPU/GPU 型号、内存、线程数、并行度、缓存状态与限额。远程模型排队时间计入用户可感知墙钟时间，并另报服务计算信息（若提供），不得把不可观测项写成零。共享缓存与一次性预处理的摊销规则预先确定。

真实模型实验记录提供商、精确模型标识和可用的版本日期、温度、top-p、种子支持情况、采样数量、最大输出长度、上下文窗口、请求顺序与重试策略。保留 prompt/completion 的原文或合规可发布版本、输入/输出/缓存/推理 token（接口可提供时）、请求时间、延迟和账单口径。费用采用实验发生时的公开或实际计费价格，记录币种和税费/折扣口径；不要将未知 token 或不可见推理量估为零。

## 6. 指标与统计分析

主要目标建议冻结为：同一标准单元库和时序约束下的映射面积，且要求设计功能通过整体验证并满足时序可行性。若尚未实现映射与时序评估，只能讨论抽象结构指标，不能回答关于 PPA 的 RQ2。功耗需要明确活动因子/向量、频率、负载和工具模型；缺少功耗证据就不宣称完整 PPA 改善。若投稿论断包含布局布线后收益，必须补齐一致物理流程与失败记录。

同时报告参考与候选绝对值、改善比例、时序约束与裕量、运行成本、峰值内存和 Pareto 权衡。面积比率以相同参考设计为分母；时序失败不能混入有效面积改善。最终流程允许回退原设计，但须同时报告回退率、搜索收益与回退后的部署指标。

完整计数包括：入选实例、请求/候选总数、去重后候选数、解析失败、接口/语义非法、外部假设不满足、环境蕴含失败、契约不可满足、局部不等价、整体验证失败、验证/综合超时、工具崩溃、服务错误、预算耗尽、等价但无收益、有效改进及回退。重试仍计入资源消耗；缺失数据必须有原因。不得只统计成功完成的请求。

对随机方法预先固定重复种子/独立运行次数，采用相同实例上的配对比较。首要聚合方式对设计家族等权：先在各 family 内按预先固定规则汇总配对效应，再对 family 汇总，避免某个参数生成器产生大量相似实例而主导结论。

置信区间使用以 family 为重采样单位的配对 cluster bootstrap；所有方法在一次重采样中使用相同 family 索引，保留家族内的实例和重复运行关系。默认报告预先固定的 95% 区间，并记录重采样次数、种子、统计量和百分位/其他区间方法。若另做 family→实例→运行的层级 bootstrap，作为敏感性分析并说明依赖假设。独立家族太少时，区间本身不可靠，应展示完整 family 级结果并限制泛化，不用大量重复种子冒充独立样本。

主要终点、聚合方法、异常值规则与实际意义阈值在正式运行前登记。不要只用 p 值代表工程价值；多种目标和多项探索性比较应标注探索性质，并在需要时处理多重检验。

## 7. 负对照与验证门禁

以下是计划要求，不能在未运行前写成已全部通过：

- 注入具有确定反例的逻辑错误，包括未改动输出之外的第二输出错误，验证门禁应拒绝。
- 使用 C=false 或矛盾契约，确认空真命题不会进入接受集合。
- 构造局部 C⇒F=F′ 成立但 A⇒C(B(x)) 不成立的实例，确认不能被批准替换。
- 将 A 设为不可满足，或尝试由模型覆盖 A、参考电路与边界，确认被拒绝；对于形式上可满足但没有真实规格依据的 A，流程不得把公式检查误报为外部合法性证明。
- 输入超过 16 个、超出 AST/求值预算或错误 schema，检查拒绝/INCONCLUSIVE 路径，不得默认为成功。
- 使用已无明显冗余的设计或原样返回候选，检验优化统计不会把无变化当收益；随机/打乱反馈用于检测仅增加上下文或尝试次数带来的伪收益，成本应匹配。
- 对固定小规模样例用独立 SAT/等价工具交叉检查；对 AST→Verilog→工具输入的转换执行独立一致性验证，以降低自写 checker 与导出器共享错误的风险。

故意取消门禁的对照只能离线计算潜在错误率，产物不得进入最终设计。

## 8. 可复现产物与可信链

每次实验保存不可变 manifest：源码提交、依赖锁定、工具版本/二进制或容器摘要、基准及许可清单、划分、固定 A 的来源及哈希、原始 F/B、契约 C、配置、种子、预算和时间。每个候选关联原始模型请求/响应、解析后 AST、来源标识、证明输入、结果状态、反例、超时/退出码、综合输入与输出、指标提取日志。派生文件用内容哈希连接，图表只从已保存原始结果生成。哈希可揭示内容变化，本身不能证明日志真实或证明器正确。

支持时保存形式工具的可复核证明证书和独立检查结果；不支持证书时明确记录工具信任边界，不能声称已获得 proof-carrying artifact。模型只负责提议，可信驱动、解析器、checker、形式工具、综合器与统计脚本的职责分别写明。

提供最小重现命令与预期输出格式，区分无需凭证的 deterministic pilot 和需要模型账户/工具许可的正式运行。不得保存 API key。归档冻结结果及失败案例，禁止以更新模型重新生成的结果替代原报告却不更改版本。

## 9. 投稿前判断

只有 pilot、没有真实模型实验、没有公平强基线、没有可信外部契约来源、无法说明方法新意，或仍将结构代理量冒充 PPA 时，不能以已完成的 DAC 实验论文投稿。现实规模、整体形式验证与目标匹配的 PPA 证据是必须解决的问题，不得以文字补全。零收益并不要求隐藏结果，但会要求重新评估论文主张和适合的投稿形式。

## 研究问题

模型可提出局部电路 F 的替代 F'，但不能自行修改外部合法输入条件 A。对于边界映射 B 和局部契约 C，应用改写前必须分别验证：

1. A 非空，且所有合法外部输入均保证 C(B(x))。
2. 所有满足 C 的局部输入均保证 F(u)=F'(u)。
3. 边界映射与组合上下文保持一致；最终流程还应独立检查完整电路等价。

例如 mux(s,a,b) 在 s=1 下可化简为 a，但若实际环境允许 s=0，这个局部证明不能授权替换。

正确性依据属于基础组合推理。需要进一步验证的技术贡献是条件提取/反馈机制是否在公平预算下胜过传统优化与LLM基线。

## 运行

需要 Node.js 22 或更新的标准运行时；没有第三方依赖，无需 npm install。

```sh
node tests/checker.test.mjs
node src/run_pilot.mjs --out results
```

当前原型穷举最多16个Boolean输入，接受严格JSON AST，支持 input、const、not、and、or、xor、mux、多输出、外部假设及边界映射。它不解析通用Verilog，不支持X/Z、时序状态或模拟电路。输入错误、超出检查预算和无法完成证明均不允许应用。

试验使用固定的人工设计候选（由AI协助编写），标记为 deterministic-pilot。共有27个局部检查用例：21个通过、6个拒绝；另有3个完整上下文示例，两个允许应用，一个因环境不能支持前提而拒绝。具体测试总数以保存的测试报告为准。这些数字只表明程序通过所列验证用例，不能解释为模型准确率、独立基准成绩或硬件性能收益。

门数与深度均是AST结构代理量，不能替代面积、时延和功耗。实际LLM模型调用与SAT/SMT、综合流程尚待接入；候选接口说明见 [LLM proposal protocol](docs/LLM_PROPOSAL_PROTOCOL.md)。
